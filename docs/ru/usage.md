Зарегистрированные пользователи работают через слеш-команды, меню с кнопками или web-чат. Слеш-команды - текстовые команды, начинающиеся с `/`. Меню с кнопками - сообщения бота с кнопками, если бэкенд их поддерживает. Администраторы используют тот же слой команд из мессенджеров или через [Local CLI](applications.md#booking-resources-cli).

Аргументы команд разделяются пробелами. Большинство значений с пробелами нужно брать в кавычки:

```text
/add_resource "Meeting room" "Room with projector" "Return the key after use"
```

В описаниях команд `<argument>` означает обязательный аргумент, `[argument]` - необязательный аргумент, а `[argument...]` - необязательный аргумент, который может содержать несколько значений или весь оставшийся текст команды.

Одно сообщение может содержать несколько слеш-команд на разных строках. Перевод строки начинает новую команду только вне кавычек и без экранирования обратной косой чертой. Поэтому quoted-значения и текст с продолжением через `\` могут содержать реальные переводы строк.

```text
/help
/list_resources
/add_resource "Meeting room" "Room with projector" "Return the key
after use"
```

Аргументы длительности принимают минуты числом или число с единицей. Английские единицы принимаются всегда: `m`, `min`, `minute`, `minutes`; `h`, `hr`, `hour`, `hours`; `d`, `day`, `days`; `w`, `week`, `weeks`; `mo`, `mon`, `month`, `months`. Для текущей локали принимаются локализованные формы, например `5 минут`, `2 часа`, `1 день`, `1 неделя`, `1 месяц` в русской локали. Для команд, которые хранят длительность в минутах, один месяц считается как 30 дней.

## Пользовательские команды

| Команда | Аргументы | Описание |
| --- | --- | --- |
| <a id="cmd-start"></a>`/start` | нет | Показать стартовое сообщение. |
| <a id="cmd-help"></a>`/help` | `[command]` | Показать доступные команды бота и подробную справку по использованию команды. |
| <a id="cmd-menu"></a>`/menu` | нет | Открыть интерактивное меню, если бэкенд поддерживает кнопки. |
| <a id="cmd-free-resources"></a>`/free_resources` | нет | Показать ресурсы, которые сейчас свободны. |
| <a id="cmd-list-resources"></a>`/list_resources` | нет | Показать все видимые ресурсы, кроме отключённых. |
| <a id="cmd-soonest"></a>`/soonest` | `[count]` | Показать ресурсы, которые освободятся раньше остальных. По умолчанию `5`, максимум `20`. Нечисловое или неположительное значение отклоняется. |
| <a id="cmd-queue"></a>`/queue` | `<name>` | Показать очередь и расписание ресурса. |
| <a id="cmd-list-users"></a>`/list_users` | нет | Показать пользователей внутри групповой области смотрящего. Администратор видит полные данные только управляемых пользователей. |
| <a id="cmd-occupy"></a>`/occupy` | `<name> [duration...]` | Занять ресурс или встать в очередь, если он уже занят. Если duration не указана, бот предложит разрешённые длительности. `0` означает бессрочно, если это разрешено. |
| <a id="cmd-release"></a>`/release` | `<name>` | Освободить ресурс, занятый текущим пользователем. |
| <a id="cmd-release-all"></a>`/release_all` | нет | Освободить все ресурсы, которые сейчас занимает текущий пользователь. Ожидание в очереди и записи расписания не снимаются. |
| <a id="cmd-schedule"></a>`/schedule` | `<name> <start> [end...]` | Запланировать ресурс на интервал. Пустой end означает бессрочно. Формат даты/времени задаётся `ui.date_time_format`; ISO-ввод тоже принимается. Используйте `0` как start, чтобы ждать освобождения; тогда `[end]` считается длительностью. Читаемое значение start `"при освобождении ресурса"` тоже принимается. |
| <a id="cmd-unschedule"></a>`/unschedule` | `<name>` | Удалить запись расписания текущего пользователя для ресурса. |
| <a id="cmd-user-settings"></a>`/user_settings` | `<action> [key] [value...]` | Показать, прочитать или изменить персональные настройки. |
| <a id="cmd-statistics"></a>`/statistics` | `<resources> <users> <start> <end|now> [format] [report_kind]` | Построить отчёт статистики. Если статистика выключена, команда и [`/help`](#cmd-help) `/statistics` отвечают, что она недоступна. Если задано `stats.admins_only`, не-админ получает отказ в доступе. |

Настройки пользователя:

| Ключ | Значения |
| --- | --- |
| `locale` | `default`, `auto`, `messenger` или код локали вроде `en`, `ru`, `ru_stand`. В web-интерфейсе `default` берёт язык браузера и сводится к `en` или `ru`. |
| `timezone` | `default`, `auto`, `system`, `UTC+03:00`, `+03:00`, `03:00`, `-03:00` или минуты вроде `180`. |
| `occupation.notify` | `all`, `mine`, `off`; также принимаются `all_resources`, `own`, `own_resources`, `disabled`. `mine` отправляет уведомления только об изменениях занятости с участием текущего пользователя. |

`ru_stand` - специальный русский вариант, который сохраняет русскоязычный интерфейс, но использует термины `стенд` / `стенды` вместо `ресурс` / `ресурсы`.

Примеры:

```text
/occupy Printer 5 мин
/occupy Printer 5 минут
/occupy Printer 2 часа
/schedule Printer "2026-02-03 10:00" "2026-02-03 12:00"
/schedule Printer 0 5 мин
/schedule Printer 0 5 минут
/schedule Printer 0 2 часа
/user_settings set locale ru
/user_settings set locale ru_stand
/user_settings set timezone UTC+03:00
```

[`/statistics`](#cmd-statistics) принимает необязательный формат вывода `csv`, `table` или `all`; по умолчанию используется `csv`. Фильтры ресурсов и пользователей задаются списками через запятую, а `all`, `-` или `none` означают все объекты, разрешённые вызывающему, но не объекты родительских или соседних групп. Администратор группы получает только полностью администрируемые ресурсы/пользователей, обычный пользователь — собственную активность и видимые ресурсы. Старые строки статистики без сохранённого снимка групп доступны только серверным/корневым администраторам. Значения `report_kind`: `utilization`, `user_activity`, `top_resources`, `peak_hours`, `plan_vs_actual`, `weekday_pattern`, `duration_distribution`, `initiators`, `events`; синонимы: `utilization_summary`, `user_activity_summary`, `top`, `peak`, `scheduled_vs_actual`, `session_duration_distribution`, `initiator_analysis`, `event_log`, `events_log`. Время начала и окончания берётся в текущем `ui.date_time_format`; при ошибке указывается ожидаемый формат. Команда скрыта из `/help`, когда статистика выключена или ограничена, но ввод [`/statistics`](#cmd-statistics) или [`/help`](#cmd-help) `/statistics` всё равно отвечает отказом, а не «неизвестная команда».

## Админские команды

Настройки сервера во время работы хранятся в SQLite и меняются через [`/server_settings`](#cmd-server-settings).

| Команда | Аргументы | Описание |
| --- | --- | --- |
| <a id="cmd-blacklist"></a>`/blacklist` | нет | Показать пользователей в чёрном списке. |
| <a id="cmd-pending-access"></a>`/pending_access` | нет | Показать недавно замеченных пользователей, ожидающих активации доступа. Требует доступ серверного администратора, потому что ожидающие идентификаторы ещё не имеют группы. |
| <a id="cmd-server-settings"></a>`/server_settings` | `<action> [key] [value...]` | Показать/прочитать/изменить настройки сервера во время работы. Требует доступ серверного администратора. |
| <a id="cmd-occupation-durations"></a>`/occupation_durations` | `<action> [duration...]` | Показать/добавить/удалить разрешённые длительности занятости. Требует доступ серверного администратора. `0` означает бессрочно. Неизвестное действие отклоняется (`list`, `add`, `remove`). |
| <a id="cmd-send-notification"></a>`/send_notification` | `[recipients] [message...]` | Отправить оповещение. Все группы получателя должны администрироваться отправителем; список `<messenger:id>` через запятую задаёт конкретных управляемых пользователей. Неразобранные или неизвестные ключи сообщаются, а не пропускаются. |
| <a id="cmd-add-resource"></a>`/add_resource` | `<name> <description> <start-message> [groups]` | Добавить ресурс. Используйте `""` для пустого описания или стартового сообщения. Если группы опущены, назначаются все корни администрируемых поддеревьев; явные группы — пути через `/` и запятую, например `office/floor1`. |
| <a id="cmd-update-resource"></a>`/update_resource` | `<name> <description> <start-message> [status] [groups]` | Обновить ресурс. Статусы для ввода: `On`, `TemporarilyUnavailable`, `Off`. Необязательные группы используют те же правила пути, что и [`/add_resource`](#cmd-add-resource). |
| <a id="cmd-delete-resource"></a>`/delete_resource` | `<name>` | Удалить ресурс. |
| <a id="cmd-add-user"></a>`/add_user` | `<messenger:id> [first] [last] [admin] [groups]` | Активировать доступ для пользователя. Если группы опущены, назначаются все корни администрируемых поддеревьев. Имя и фамилию можно опустить, чтобы взять данные профиля мессенджера. `admin` принимает `1`/`0`, `true`/`false`, `yes`/`no`, `on`/`off` или `admin`/`user`. |
| <a id="cmd-update-user"></a>`/update_user` | `<messenger:id> [first] [last] [admin] [groups]` | Обновить существующего пользователя. Имя и фамилию можно опустить, чтобы сохранить текущие значения. `admin` использует те же значения, что и [`/add_user`](#cmd-add-user); неверный флаг отклоняется. |
| <a id="cmd-delete-user"></a>`/delete_user` | `<messenger:id>` | Удалить пользователя. |
| <a id="cmd-ban-user"></a>`/ban_user` | `<messenger:id> <duration> [reason...]` | Заблокировать пользователя. Длительность принимает минуты, часы, дни, недели, месяцы или бессрочное значение; используйте `permanent`, `perm`, `forever` либо русские `навсегда`, `навс`, `навечно`. |
| <a id="cmd-unban-user"></a>`/unban_user` | `<messenger:id>` | Удалить пользователя из чёрного списка. |

Стандартные длительности занятости: `0`, `5`, `30`, `60`, `120` и `240` минут. `0` означает бессрочно и не удаляется. Статусы ресурса для ввода в командах: `On` (`on`, выводится как `Включён`), `TemporarilyUnavailable` (`temporarily_unavailable` или `temporarily-unavailable`, выводится как `Временно недоступен`) и `Off` (`off`, выводится как `Выключен`).

Примеры управления длительностями: `/occupation_durations add 5 минут`, `/occupation_durations add 2 часа`, `/occupation_durations remove 1 час`.

Для [`/ban_user`](#cmd-ban-user) длительность из двух слов можно писать в кавычках или без них перед причиной: `"5 минут" spam` и `5 минут spam` оба означают блокировку на 5 минут с причиной `spam`.

Значения флага администратора для команд пользователей: `1`, `true`, `yes`, `y`, `on`, `admin` или локализованные варианты включают роль; `0`, `false`, `no`, `n`, `off`, `user` или локализованные варианты отключают роль. Роли по группам вводятся как `user` и `admin`:

```text
group=user,group/subgroup=admin
```

У администратора группы явно указанные группы должны совпадать с администрируемым корнем или быть
его потомками. `-` либо явно пустая группа означают `Корневая группа (все группы)`, поэтому такое
значение доступно только серверному/корневому администратору. Для изменения или удаления
многогруппового пользователя/ресурса нужны права на все затронутые группы. Операции чёрного списка
проверяют группы активной цели; неизвестный ключ может блокировать или разблокировать только
серверный/корневой администратор.

Примеры:

```text
/add_user telegram:1234 John Doe да
/add_user telegram:1234 "" "" администратор
/update_user telegram:1234 admin
/add_resource "Printer" "Color laser printer" "Load paper before use" "office/floor1"
/ban_user telegram:1234 "5 минут" "spam"
/ban_user telegram:1234 2 часа "spam"
/server_settings set menu.update_mode passive
```

## Меню

Открыть меню:

```text
/menu
```

`Главное меню` содержит:

- `Занятие ресурсов`.
- `Список пользователей`, который открывает страницу `Пользователи с активным доступом`.
- `Статистика`, если она включена для текущего пользователя.
- `Настройки пользователя`.
- `Администрирование`, только для админов.

`Занятие ресурсов` содержит:

- `Карточки ресурсов`.
- `Свободные ресурсы`.
- `Скоро освободятся`.
- `Освободить занимаемые ресурсы`, если текущий пользователь прямо сейчас занимает минимум два ресурса.
- `Обзор ресурса` с действиями `Занять`, `Освободить`, `Посмотреть очередь` и `Запланировать`, когда они применимы.

Список `Скоро освободятся` начинается с `5` ресурсов и предлагает кнопку `Показать больше`, чтобы расширить список до `10`.

`Настройки пользователя` содержат:

- `Язык`.
- `Временная зона`.
- `Уведомления о занятости ресурсов`.

`Администрирование` содержит:

- `Управление ресурсами`.
- `Управление пользователями`.
- `Пользователи, ожидающие активации доступа`.
- `Отправить оповещение пользователям`.
- `Чёрный список пользователей`.
- `Длительности занятости ресурсов`.
- `Настройки сервера`, только для серверных администраторов.

Меню хранит сессию на пару чат/пользователь. По умолчанию сессия меню истекает через 30 минут неактивности. В режиме `active` открытые меню обновляются после изменений моделей; в режиме `passive` меню показывают отдельные кнопки обновления.

## Local CLI

[Local CLI](applications.md#booking-resources-cli) подключается к запущенному [`booking-resources-server`](applications.md#booking-resources-server) или [`booking-resources-web`](applications.md#booking-resources-web). Подключение к серверу пересылает слеш-команды как локальный админский пользователь. Подключение к web отправляет команды управления web-пользователями в SQLite web-процесса; серверная [`/add_user`](#cmd-add-user) при этом не вызывается. `Ctrl+C` отключает CLI от текущего процесса и не останавливает server или web.

Основные команды:

```text
booking-resources-cli --list
booking-resources-cli --pid <server_pid>
booking-resources-cli --pid <server_pid> --command "/help"
booking-resources-cli --pid <server_pid> --command "/server_settings list"
booking-resources-cli --web-shared-memory-key <web_key>
booking-resources-cli --web-shared-memory-key <web_key> --command "/list_users"
```

В интерактивной оболочке:

```text
\list
\connect <pid>
\connect web <web_key>
/help
/add_resource "Printer" "" ""
\quit
```

В TTY Up/Down листает предыдущие команды этого процесса CLI, а Tab дополняет метакоманды, слеш-команды и аргументы. См. [booking-resources-cli](applications.md#booking-resources-cli).

Через серверное подключение [Local CLI](applications.md#booking-resources-cli) принимаются только админские команды. Просмотровые [`/list_resources`](#cmd-list-resources), [`/list_users`](#cmd-list-users), [`/free_resources`](#cmd-free-resources), [`/soonest`](#cmd-soonest) и [`/queue`](#cmd-queue) там доступны. Пользовательские команды вроде [`/occupy`](#cmd-occupy), [`/release`](#cmd-release) или [`/release_all`](#cmd-release-all) отклоняются.

Web-подключение [Local CLI](applications.md#booking-resources-cli) принимает:

| Команда | Описание |
| --- | --- |
| `/help [command]` | Список команд web Local CLI с кратким описанием. С именем команды показывает использование и дополнительные детали. |
| `/list_users` | Список web-пользователей: логин, `web:<uuid>`, имя, locale, provider и задан ли пароль. |
| `/add_user <login> <first_name> [last_name] [locale]` | Создаёт web-пользователя с локальным логином/паролем без рабочего пароля и печатает одноразовую ссылку на `/set-password.html`. Требует `log-in-only` или `log-in-with-registration`. |
| `/delete_user <login\|user_id\|web:uuid>` | Удаляет локального web-пользователя, учётные данные, сессии, события, файлы, кэш команд и токены пароля. Серверная учётка `web:<uuid>` не меняется. |
| `/reset_password <login\|user_id\|web:uuid> [login]` | Сбрасывает текущий пароль и выдаёт одноразовую ссылку на 1 день. У существующей учётки с логином/паролем это `/reset-password.html`. Для пользователя без логина нужен `[login]`, ссылка ведёт на `/set-password.html`. Требует `log-in-only` или `log-in-with-registration`. |

Ссылки на пароль используют `web/public_https_host`, если он задан. Иначе CLI печатает localhost-origin и пишет, что для раздачи ссылки снаружи нужен `web/public_https_host`.

## Web-интерфейс

Web-интерфейс отдаётся приложением [`booking-resources-web`](applications.md#booking-resources-web).

Страницы:

| Страница | Назначение |
| --- | --- |
| `/` или `/index.html` | Стартовая страница со ссылкой на чат. |
| `/authorize.html` | Создание или восстановление сессии web-пользователя одним из включённых способов авторизации. |
| `/set-password.html` | Публичная страница первичной установки пароля по одноразовому токену `set_password`. Назначенный логин показывается только для чтения. |
| `/reset-password.html` | Публичная страница сброса пароля по одноразовому токену `reset_password`. |
| `/chat.html` | Браузерный чат для слеш-команд, кнопки меню команд, сообщений бота, файлов, кнопок, подсказок команд и панели настроек внутри чата. В тексте сообщений адреса `http(s)`, `www.` и `mailto:` становятся кликабельными ссылками. |

Основной сценарий `sign-without-registration`:

1. Открыть `/authorize.html`.
2. Ввести имя, необязательную фамилию и локаль.
3. Web-процесс создаст новый идентификатор пользователя `web:<uuid>` и запишет его на сервере как ожидающего активации доступа.
4. Скопировать `web:<uuid>` из служебного сообщения чата до активации доступа или из панели настроек и передать его администратору.
5. Администратор активирует доступ именно для этого ключа через [`/add_user`](#cmd-add-user) `web:<uuid> ...` или через админское меню.
6. Использовать `/chat.html` как чат с ботом.

Если [`booking-resources-web`](applications.md#booking-resources-web) включает `log-in-with-registration`, `/authorize.html` также показывает регистрацию и вход по локальному логину/паролю. Регистрация всё равно создаёт сгенерированный `web:<uuid>` и записывает его на сервере как ожидающего активации доступа. `log-in-only` показывает только вход: администратор создаёт учётку через web [Local CLI](applications.md#booking-resources-cli) `/add_user` без рабочего пароля; такой пользователь открывает `/set-password.html` по напечатанной ссылке и затем входит на `/authorize.html`. Тот же сценарий Local CLI работает и при `log-in-with-registration`. Последующие входы используют локальный логин/пароль только для восстановления того же web-идентификатора и выдачи новой cookie `br_session`; серверная идентичность и права остаются привязаны к `web:<uuid>`. Авторизованный пользователь с локальным логином/паролем может сменить пароль в панели настроек чата; логин фиксируется после назначения. `sign-without-registration` можно сочетать с одним login-способом.

Формы авторизации и настроек предлагают локали `en`, `ru` и `ru_stand`. Вариант `ru_stand` сохраняет русскоязычный интерфейс, но использует термины `стенд` / `стенды` вместо `ресурс` / `ресурсы`.

Для `log-in-with-registration` регистрация проверяет `login` как строку длиной 3-128 символов из букв, цифр, `.`, `_`, `@`, `+` и `-`. Пароль должен содержать минимум 8 символов и не должен включать управляющие символы.

Web-сессия хранится в cookie `br_session` с `HttpOnly` и `SameSite=Lax`; cookie получает `Secure`, когда активен HTTPS или внешний HTTPS. История чата и кэш команд хранятся локально в браузере и привязаны к web-идентификатору пользователя.

Кнопка слева от поля ввода сообщения открывает полный список слеш-команд. Ввод `/` по-прежнему фильтрует подсказки команд прямо в поле ввода. Enter отправляет текущее сообщение. Shift+Enter вставляет перевод строки. Несколько слеш-команд и quoted-переносы в web-чате подчиняются тем же правилам, что и в разделе команд выше.

Панель настроек внутри чата также включает локальные для браузера выбор темы и лимит локальной истории (`20`-`1000` сообщений), очистку локальной истории и выход из сессии. Локаль хранится на web-стороне через `POST /api/profile` и остаётся редактируемой даже до активации серверного доступа. Пункт «По умолчанию» берёт язык браузера (`navigator.language` / `Accept-Language`) и сводится к `en` или `ru`; `ru_stand` используется только при явном выборе. Веб-интерфейс сначала показывает язык браузера (`en` или `ru`), затем накладывает сохранённую локаль профиля или `/api/user-settings`. Временная зона и уведомления о занятости - это серверные настройки через `/api/user-settings`; до активации доступа эти элементы остаются недоступными. Кнопка `OK` в этом случае остаётся активной, чтобы можно было сохранить локаль, тему и лимит локальной истории. Если настройки пользователя не удалось загрузить из-за недоступности web-сервера, сервера или самих настроек, кнопка `OK` неактивна.

Если браузер не может достучаться до [`booking-resources-web`](applications.md#booking-resources-web), чат показывает `Web-сервер недоступен.` и скрывает поле ввода. Если web-процесс работает, а [`booking-resources-server`](applications.md#booking-resources-server) недоступен по IPC, чат показывает `Сервер недоступен.` Авторизация и серверные настройки показывают тот же текст `Сервер недоступен.`, когда действие требует сервер.

Публичные API-маршруты:

| Маршрут | Описание |
| --- | --- |
| `GET /health` | Публичный liveness endpoint, который возвращает компактный JSON-ответ. |
| `GET /api/runtime-config` | Возвращает настроенный заголовок страницы и включённые способы web-авторизации. |
| `GET /api/i18n?locale=<locale>` | Возвращает словарь web-интерфейса. |

API-маршруты с web-сессией:

| Маршрут | Описание |
| --- | --- |
| `GET /api/session` | Возвращает профиль текущей web-сессии. |
| `POST /api/profile` | Обновляет локаль текущего web-пользователя/сессии. |
| `GET /api/commands?locale=<locale>` | Возвращает данные доступных команд и подсказки для запрошенной или текущей локали. |
| `GET /api/user-settings` | Читает серверные настройки пользователя. |
| `POST /api/user-settings` | Обновляет серверные настройки пользователя. |
| `POST /api/messages` | Отправляет сообщение чата на сервер. |
| `POST /api/callbacks` | Отправляет событие нажатия кнопки на сервер. |
| `GET /api/events` | Возвращает `{ ok, events, server_available }` с ожидающими событиями/сообщениями бота для web-пользователя. `server_available` равен `false`, пока IPC с сервером недоступен. Поддерживает необязательный long-poll параметр `wait=<ms>` с ограничением до `25000` мс; ожидание пропускается, пока сервер недоступен. |
| `GET /api/files/<id>` | Скачивает файл, доступный от бота. |
| `POST /api/account/password` | Меняет локальный пароль текущего web-пользователя, если включён `log-in-only` или `log-in-with-registration`. Логин не изменяется. |
| `POST /api/logout` | Отзывает текущую web-сессию, если она есть, и очищает cookie. |

Маршруты авторизации:

| Маршрут | Описание |
| --- | --- |
| `POST /api/authorize` | Создаёт локального web-пользователя/сессию через `sign-without-registration` и записывает web-пользователя на сервере как ожидающего активации доступа. |
| `POST /api/register` | Создаёт локальную учётную запись с логином/паролем и сгенерированным web-идентификатором, если включён `log-in-with-registration`. |
| `POST /api/login` | Проверяет локальный логин/пароль и выдаёт web-сессию для существующего web-идентификатора, если включён `log-in-only` или `log-in-with-registration`. |
| `GET /api/account/password-token` | Возвращает логин и назначение одноразового токена пароля. Публичный. |
| `POST /api/account/password-set` | Задаёт первый пароль по токену `set_password`. Публичный. Cookie `br_session` не ставит. |
| `POST /api/account/password-reset` | Задаёт новый пароль по токену `reset_password`. Публичный. Cookie `br_session` не ставит. |

`POST /api/authorize`, `POST /api/register`, `POST /api/login`, `GET /api/account/password-token`, `POST /api/account/password-set` и `POST /api/account/password-reset` используют общий rate limit: `10` попыток с одного удалённого адреса за `60` секунд при глобальном лимите `100` попыток за `60` секунд.
